# orion-site

Project Orion website and administration panel.

## Команда и права доступа

Панель `admin.php` использует иерархические роли:

1. `admin` — глава/создатель, полный доступ и управление проектом.
2. `orion_council_head` — глава совета Ориона, управление командой, модерацией и публичными материалами.
3. `developer` — разработка и технические системы.
4. `senior_moderator` — обработка и удаление репортов, без доступа к игрокам.
5. `moderator` — только обработка репортов, без доступа к аккаунтам и блокировкам игроков.
6. `content_maker` — публикация контента.
7. `player` — базовый аккаунт без доступа к панели.

Роль задаёт базовые разрешения. Администратор может добавить персональный `allow` или `deny` для отдельного разрешения во вкладке «Роли и доступы». Сотрудник не может изменять себя или аккаунт равного/высшего уровня.

Все роли команды участвуют в ГСО: могут подавать предложения и голосовать. Принятое
большинством решение проверяет глава совета, после чего оно попадает главе проекта во вкладку
«РЕАЛИЗОВАТЬ». Обычные игроки имеют только доступ к просмотру палаты и архива голосований.

Схема создаётся автоматически из `db.php`: поле `accounts.staff_role`, таблица персональных исключений `staff_permission_overrides` и журнал `staff_action_log`. Старые аккаунты с `is_admin = 1` автоматически сохраняют роль администратора.

## Привязка Discord

В личном кабинете доступна OAuth2-привязка Discord с минимальным scope `identify`. Данные приложения
и точный `DISCORD_REDIRECT_URI` находятся в `discord_config.php`; этот же URI нужно добавить в
Discord Developer Portal. Discord ID и username сохраняются в базе, а OAuth access/refresh tokens
хранятся только в зашифрованном виде для автоматической синхронизации username. Client Secret
нельзя публиковать в Git; после случайной публикации его нужно перевыпустить в Discord Developer Portal.
